# 单样本修复的机制与验证边界

## 两种已配置策略

载荷策略恢复已校验字节，并在运行时原解密调用点复制；
原生调用策略按固定构建保护条件处理一个本地启动调用。
两种策略分别使用自己的身份和参数，不依赖其他 EXE 的字节作为目标补丁。

## 字段与实现约束

| 项目 | 当前处理 |
| --- | --- |
| 注册门与载荷链 | 载荷策略同时处理已定位控制流与正确字节 |
| CRC 分支 | 保留实际完整性校验，不将失败标志改为成功 |
| 派生输入 | 仅对配置验证的 32 位分量域执行有界结构筛选 |
| 原密文 | 保留原始字节，在对应运行点复制恢复载荷 |
| 描述符 `+0` | 是启用字段；不作为目标 RVA |
| 原 PRGA 栈约定 | helper 使用 `RET 8`，由机器码测试检查 |
| 新构建 | 按完整 SHA-256 与长度匹配；未配置身份拒绝处理 |
| 原生调用分支 | 静态构建，不执行载荷捕获和搜索 |

## 用例链

载荷策略：`inspect()` → 配置匹配 → 校验清单或首次捕获/恢复 →
全载荷 CRC/SHA-256 → `build_repair()` → 发布与重放。

原生策略：`inspect()` → 配置匹配 → `build_native_repair()` →
引擎、重定位、容器和候选检查 → 共用发布与重放。

## 分开记录的验收

1. 文件级：输入摘要、输出范围、引擎往返和补丁重放。
2. 运行级：真实窗口、外部资源、交互、退出原因。
3. 可恢复性：独立副本执行回滚后与原字节完全一致。

清单、日志和生成副本不保存注册码或恢复过程中使用的派生值。
合成测试的通过范围见 [测试文档](../tests/README.md)，具体策略见
[载荷流程](ENIGMA_RUNTIME_REPAIR.md) 与 [原生流程](EXHIBIT_DMM_REPAIR.md)。
