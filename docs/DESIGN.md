# 设计与模块边界

## 分层与依赖方向

`domain` 定义数据契约；`security` 提供纯算法；`formats` 解析字节结构；
`workflows` 将已匹配的配置转换为候选字节；`adapters` 连接文件系统、DLL、
运行时捕获和计算设备；`application` 编排用例与发布；
`cli`、`ui` 呈现应用结果。

领域层与算法层不导入外层模块，格式层不依赖应用或界面，应用层不导入 Tk。
这些边界由 `test_architecture.py` 检查。相应接口见各目录 README。

## 容器加载与提取

1. `ProgramLoader.load()` 读取源文件并检查外壳为 PE32。
2. 用节表末尾定位 Overlay，选择 V1–V7 配置布局。
3. 对配置复制出的缓冲区做 XOR 变换，核对 CRC32。
4. 内嵌主程序从配置对齐后的区域读取；外置主程序按合法相对名称读取。
5. `ProgramExtractor.extract()` 复制主程序字节，依照区块模式选择文件偏移或 RVA。
6. 文件资源先复制再局部修改；进度回调和失败记录逐个区块返回。

| 版本 | 配置大小 | 补丁数量 | 配置对齐 |
| --- | ---: | ---: | ---: |
| V1 | `0x140` | 16 | `0x1000` |
| V2 | `0x1180` | 16 | `0x2000` |
| V3 | `0x1280` | 16 | `0x2000` |
| V4–V7 | `0x9540` | 256 | `0x10000` |

路径策略拒绝容器中的盘符、根路径和上级目录。区块失败不会被记作整体成功；
其他区块仍按提取器的循环继续处理。提取器与修复事务的覆盖规则不同。

## 修复策略与发布

`identify_profile()` 同时检查完整摘要和长度。`RepairProfile` 走载荷恢复策略，
`NativeCallProfile` 走静态原生调用策略，`DiscCheckProfile` 走光盘检查兼容策略，
三者共用 `RepairService` 的发布层。
未命中已知身份时保留现有原生结构发现；光盘检查配置不走猜测偏移的回退。
无法建立支持的配置会返回 `RecoveryError`，不按文件名或相近版本复用偏移。

可选 `PortableSetupProfile` 将安装目录调用点与字符串 ABI 参数集中为不可变配置。
`portable_setup` 只产生代码、替换点和保护条件，不读取注册表或写文件；
`disc_repair` 负责与已有运行时保护合并。名称仅用于报告，不参与能力选择。
这种拆分使范围、冲突、UTF-16 和调用约定可以用合成输入独立回归。

载荷策略的缓存先重新验证；无有效缓存时才延迟导入捕获与恢复依赖。
构建器输入是字节、配置、载荷和压缩回调，输出为 `BuiltRepair(data, patch, report)`，
不自行写文件。构建结束重新解析 PE、重提取引擎并重放差异。

发布层验证源文件未改变，检查产物别名与覆盖冲突，依次原子写入并重读文件。
输出包括副本、原始基线、差异 JSON、验证 JSON 和回滚脚本。
单个文件的原子替换不代表多文件发布具有整体原子性。

## 状态、并发与资源生命周期

`WorkbenchState` 是不可变快照，`ConsoleController` 用可重入锁更新状态。
Tk 主线程创建控件、渲染和弹窗；后台线程执行加载或动作，队列传递结果。
加载和执行期间界面禁用重复动作。

运行时捕获只清理自己创建的探测进程、会话和临时目录。
OpenCL 适配器跟踪自己分配的句柄，反序释放；重复扫描复用输入和足够大的输出缓冲区。

## 验证层级

| 层级 | 确认内容 | 不直接证明 |
| --- | --- | --- |
| 格式与单元测试 | 字节范围、版本、边界、算法向量 | 实际目标程序环境 |
| 构建与重放 | PE 结构、引擎往返、候选摘要、重放一致 | 外部资源完整与运行成功 |
| 独立运行 | 实际窗口、资源、交互和退出原因 | 所有构建或完整流程均可用 |
| 独立回滚 | 恢复原始字节与摘要 | 新适配的运行兼容性 |

扩展处理流程时定义识别信息、参数契约和字节保护条件，
同时补充合成测试、运行记录及回滚验证。
