# 修复工作流与验证

## 工作流分组

载荷恢复流程校验并恢复载荷，在原解密调用点使用复制 helper。
原生调用流程根据保护条件生成跳板、处理重定位并封装引擎。
光盘检查兼容流程保留原打包节，在受保护的单次运行时回调中处理检查结果。
三个流程使用统一的检查、发布和回滚接口，不从参考 EXE 复制补丁。

## 参数与数据契约

| 项目 | 处理方式 |
| --- | --- |
| 输入识别 | 检查完整 SHA-256、文件长度和结构 |
| 控制流编辑 | 验证位置、原字节、记录范围和引用 |
| 完整性检查 | 保留原 CRC 校验，恢复数据另做 CRC/SHA-256 验证 |
| 恢复范围 | 在参数指定的分量域执行有界筛选 |
| 源数据 | 保留原始密文和未修改区间 |
| 载荷描述符 | 区分启用字段、源 RVA、长度与标记 |
| 调用约定 | 保持寄存器、标志、参数和栈清理约定 |
| 发布 | 输出独立副本、差异、验证记录、基线与回滚脚本 |

参数检查由 `identify_profile()`、`validate_payloads()` 和相应构建器执行。
校验失败返回结构化错误，不继续使用未经校验的偏移或记录。

## 执行链

载荷恢复：
`inspect()` → 输入匹配 → 校验清单或捕获与恢复 →
载荷 CRC/SHA-256 → `build_repair()` → 输出验证与发布。

原生调用：
`inspect()` → 输入匹配 → `build_native_repair()` →
引擎、重定位与容器校验 → 输出验证与发布。

光盘检查：`inspect()` → 精确身份及 PE 校验 → `build_disc_repair()` →
追加分离的代码/状态节 → 字节保留与差异重放 → 统一发布。
无需捕获、搜索或压缩；未知身份不套用固定偏移。

可选安装目录计划由 `PortableSetupProfile` 描述，`portable_setup` 模块负责
纯函数校验与代码生成，光盘构建器负责合并保护条件和有界 worker。
调用点、字符串函数和目录对象地址属于配置数据；构建流程不判断配置名称。
超时和保护失配均不写入，普通构建报告仍不标记实际启动已验证。

## 验证步骤

1. 文件验证：记录输入摘要、输出范围、引擎往返与补丁重放结果。
2. 运行验证：记录目标程序启动、资源加载、交互和退出结果。
3. 回滚验证：在独立副本执行回滚，再比较原始字节与摘要。

清单与输出不保存恢复过程中使用的派生值。
